# AI 修補軟體漏洞74%失敗，1Password 研究警告：AI 尚未準備好接手資安修補

## 📖 新聞導語
密碼管理公司 1Password 的安全研究團隊 Off-By-1-Labs 發布研究顯示，AI 工具在修補軟體漏洞時失敗率高達 74%——僅 26% 的修補真的可用。這個數字對正在大力推銷「AI 全自動修補」作為資安銀子彈的廠商和初創公司，無疑是一記重擊。

---

## 💡 核心內容

### 研究方法：6,080 次修補測試
研究團隊選取 6 個真實世界的漏洞（包括 Linux 權限提升、ActiveMQ 遠程代碼執行、Chrome File System Access API 的 use-after-free、EXIM 未授權 RCE、SpringAI SpEL RCE 及 Gemini CLI RCE），要求 LLM 為每個漏洞生成修補程式。在不同環境條件下、每個漏洞用 9 種精心設計的 prompt，共生成約 6,080 個修補嘗試。

### 核心數據：74% 失敗率
- **僅 26% 真正可用**：修補確實修復漏洞且不改變應用程式行為
- **21% 修補有效但改變了應用行為**：修補了漏洞，但在過程中改變了應用程式的原有功能
- **53.9% 完全失敗**：LLM 無法創建修補、引入新漏洞，或兩者兼有

### 失敗根源：「看似修補、內含缺陷」
研究發現，無論環境條件或 prompt 如何變化，LLM 生成的往往是「帶有隱藏缺陷的類修補」（Fix-Like Artifacts with Embedded Defects），這也成為研究項目命名為「FLAWED」的原因。LLM 特別掙扎於需要理解代碼庫不同部分上下文的多步驟複雜修補；對於簡單、隔離的漏洞，修補成功率較高——但這類問題人類開發者本來就能快速處理。

---

## 🔮 業界展望
這項研究揭示了 AI 在資安領域「發現快、修補慢」的根本矛盾：AI 在大規模漏洞掃描上已證明有效，但真正的自主修補能力遠未成熟。企業若急於將關鍵資安任務交給尚未準備好的 AI，既可能省了人工成本，卻帶來更大的安全風險。
