AI 修補軟體漏洞
74% 失敗

1Password Off-By-1-Labs 研究：LLM 生成 6,080 次修補僅 26% 可用，「FLAWED」揭示 AI 修補根本缺陷

📺 資料來源：ZDNet

📅 發布日期：2026-08-06

🤖 處理方式：AI 智能摘要生成

🎯 核心觀點

1Password 安全研究團隊 Off-By-1-Labs 發布研究，測試 LLM 對 6 個真實漏洞生成修補程式，結果顯示僅 26% 真正可用、21% 改變應用行為、53.9% 完全失敗。總失敗率高達 74%，揭示 AI 在資安領域「發現快、修補慢」的根本矛盾。

🔬

研究方法：6,080 次修補測試

研究團隊選取 6 個真實世界漏洞，包括 Linux 權限提升（Copy Fail）、ActiveMQ 遠程代碼執行、Chrome File System Access API 的 use-after-free、EXIM 未授權 RCE、SpringAI SpEL RCE 及 Gemini CLI RCE，在不同環境下用 9 種 prompt 共生成約 6,080 個修補嘗試。

📊

核心數據：74% 失敗率

僅 26% 真正可用；21% 修補了漏洞但改變了應用程式原有行為；53.9% 完全失敗——LLM 無法創建修補、引入新漏洞，或兩者兼有。

⚠️

失敗根源：「看似修補、內含缺陷」

無論環境條件或 prompt 如何變化，LLM 生成的往往是「帶有隱藏缺陷的類修補」（Fix-Like Artifacts with Embedded Defects），這也是研究項目命名為「FLAWED」的原因。

🤖

複雜漏洞最棘手

LLM 特別掙扎於需要理解代碼庫不同部分上下文的多步驟複雜修補；對於簡單、隔離的漏洞，修補成功率較高——但這類問題人類開發者本來就能快速處理。

📌 重點提示

AI 在漏洞發現上已證明有效，但真正的自主修補能力遠未成熟。企業若急於將關鍵資安任務交給尚未準備好的 AI，既可能省了人工成本，卻帶來更大的安全風險。
