# GPT-6 Astra變強後，Skill檔反而該大掃除！Codex工程師點名5種舊指令拖累效率

## 📖 新聞導語

GPT-6 Astra 上線後，Codex 團隊工程師 Eric Provencher 發文建議：與其幫新模型加更多 skill 和規則，不如趁機做一次「大掃除」，刪除過時、冗長或互相衝突的指令，否則只會拖慢模型效率。

## 💡 核心內容

### 為什麼 skill 裝太多反而變笨？

Skill 本質上是一份存成 Markdown 的提示詞，模型靠它的名稱和描述判斷何時該调用。每個專案的初始 skill 清單最多只能占 context 的 2%（或 8,000 個字元），超出後描述會被截短，甚至直接省略部分 skill。當描述之間互相矛盾或寫得太「選我」，模型更難做出正確選擇。

### 五步驟幫 skill 大掃除

**第一步：描述縮短到一句話**
只說「做什麼」和「何時該用」，不要寫成說明書。

**第二步：結構拆開**
把肥大的單一 SKILL.md 檔拆成「路由器 + 附件」模式，讓模型按需讀取，而非一次性載入全部內容。

**第三步：刪掉食譜式流程**
模型已能理解細微差異和模糊指令，過去「每次編輯前先讀完某幾份文件」的指令反而浪費 context。改為「哪份文件管哪件事」，讓模型自己判斷。

**第四步：把禁令改成授權**
舊模型時代的「先問再做」禁令，換到 Astra 可能導致它在你希望繼續的地方停下來。改為明確授權，並定義「完成」的標準。

**第五步：叫 Astra 自己做稽核**
提供提示詞讓 Astra 依上述原則對專案做一次完整盤點，列出修改建議，經確認後再動手。

### 兩種人不急著刪

若 repo 裡的 skill 會被同事的 agent（可能使用 Sol、Luna 等其他模型）讀到，對 Astra 剛好的指令對它們可能不夠用，仍需保留部分過渡規則。

## 🔮 業界展望

這次大掃除的重點是「寫準」不只是「寫少」。Skill 描述要精準、結構成合、授權要明確。專家建議可以「先刪描述、再拆結構」，把完成條件寫清楚後，剩下的交給模型自己判斷。
